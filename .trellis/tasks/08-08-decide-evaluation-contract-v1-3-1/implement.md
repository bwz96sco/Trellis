# v1.3.1 operator decision implementation plan

## Preconditions

- B131-1 is committed and independently readable.
- Exact author/reviewer/candidate/evidence identities are assembled.
- A genuine operator instruction is received after those facts are presented.

## Ordered work

1. Verify all exact commit, tree, manifest, semantic, member, and verdict identities.
2. Present assurance verdict, four corrected defects, and residual risks to the operator.
3. Record the explicit operator choice without inference.
4. Validate decision eligibility and all false authority flags.
5. Generate exactly one canonical decision JSON.
6. Run task, strict JSON, path, protected-byte, and authority checks.
7. Stop for separate O131-1 commit authorization.
8. After an authorized commit, stop the campaign; do not open technical work automatically.

## Stop gates

Stop on absent/ambiguous operator input, identity mismatch, failed assurance paired with acceptance, missing rationale where required, extra output, or any operational-authority request.

## Commit boundaries

O131-0 and O131-1 remain separate. No activation or commit is authorized by this planning artifact.

An authenticated B131-1 `fail` is valid decision input for reject/stop and must not be described as a missing prerequisite. Only `accept-with-rationale` requires `pass`. Every outcome terminates at STOP and carries all common false authority fields.
